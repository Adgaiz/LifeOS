# Stage 4：AI 周报/月报解释

## 模块目标

AI 周报/月报在本地确定性统计之上提供一层克制的解释。它不读取全部人生数据，也不重新计算事实指标；用户先看到本地统计，再决定本次允许 AI 看到哪些聚合结果。

本批次完成“选择周期 → 选择聚合指标 → 重新校验 → 授权发送 → 生成 → 本地保存”的闭环。日记原文、图片、行动标题和逐日原始记录都不进入请求。

## 用户流程

1. 用户在“成长趋势”页选择近 7 天或近 30 天。
2. 点击“生成 AI 周报”或“生成 AI 月报”。
3. 所有授权选项默认关闭，用户可选择状态趋势、健康趋势、行动完成和目标进度。
4. 页面展示每类聚合指标的摘要，不展示或发送内部 ID。
5. 点击授权生成时，系统重新计算所选指标；若数据变化，停止调用并要求用户刷新确认。
6. AI 返回 Markdown 解释并保存到本机；重新生成会创建新记录。

## 上下文最小化

请求始终包含周期、起止日期和记录覆盖率。只有用户勾选后才增加对应聚合数据：

- 状态趋势：平均睡眠、情绪、精力，以及前后半周期平均值和变化量。
- 健康趋势：最新体重、周期体重变化、运动天数和总分钟数。
- 行动完成：行动总数、完成数、部分完成数和完成率。
- 目标进度：进行中目标数量和当前平均进度。

请求不包含：

- Daily 逐日原始行、时区、更新时间和内部 ID。
- Action 标题、最低行动、分类、Goal ID 或每日明细。
- Goal 标题、关键结果标题或内部 ID。
- Diary 原文、标签、图片和私有路径。
- Vision、Timeline、AI Friend 历史或其他 AI 报告正文。

## 输出约束

Prompt 版本为 `1`，要求严格包含：

- 这段时间发生了什么
- 值得肯定的变化
- 可以温柔留意的模式
- 下一周期的三个小实验
- 数据边界

输出必须区分事实、可能模式和不确定性。样本少或缺失多时降低结论强度，不把相关性描述成因果，不进行医疗、心理、营养或财务诊断，不以完成率评价用户价值。

## 本地持久化

数据库 Schema 升级到版本 9，新增 `ai_periodic_reports`：

- 保存周期类型、起止日期、Markdown 内容、Provider、模型和 Prompt 版本。
- 保存本次授权的聚合指标类型、request ID 和 Token 用量。
- 不保存 API Key、完整 Prompt 或本次发送的聚合 JSON 副本。
- 报告视为不可变结果；同一周期重新生成会创建新记录。
- 页面只读取与当前日期范围完全匹配的最新报告，避免把旧周期结果误认为当前结果。

## 自动化验证

- 加载本地统计和历史报告时不调用 AI。
- 只发送用户勾选的聚合类别。
- Prompt 不包含行动标题、日记、内部 ID 或逐日原始记录。
- 生成前聚合数据变化时阻止外部调用。
- 空授权在网络调用前被拒绝。
- SQLite 可保存不可变报告并读取相同周期范围的最新版本。
- Schema 1–8 可以升级到 Schema 9 并创建查询索引。
- Widget 测试覆盖默认未授权、主动勾选、生成和结果展示。

所有自动化测试使用 Fake AI Service，不访问真实 Provider，也不产生费用。
