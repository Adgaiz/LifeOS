# Stage 3：AI 当日复盘

## 模块目标

AI 当日复盘是 AI Companion 的第一个有限业务场景。它不是评价用户一天是否“优秀”，而是基于用户本次主动选择的数据，提供一份温暖、克制、可行动的 Coach/Analyst 复盘。

本批次不实现多轮聊天、Friend、全历史读取或自动修改任务，只完成“选择上下文 → 授权发送 → 生成 → 本地保存 → 再次查看”的最小闭环。

## 用户流程

1. 用户从“今天”页进入“AI 当日复盘”。
2. 页面读取本机的今日状态、任务和日记，仅用于展示可选范围，此时不会调用 AI。
3. 所有上下文选项默认关闭；用户可以逐项勾选今日状态、今日任务、今日日记原文。
4. 点击“授权并生成复盘”后，只把本次勾选的数据发送给当前配置的 Provider。
5. AI 返回 Markdown 复盘并保存到本机；重新生成会创建新记录，不覆盖历史结果。

## 上下文最小化

- 今日状态包含用户勾选后授权的睡眠、情绪、精力、体重和运动数据。
- 今日任务包含标题、分类、完成状态和最小行动，不发送内部 ID。
- 日记属于高敏感内容，必须单独勾选；最多发送前 12000 个字符，并在请求中标记是否截断。
- Diary 图片、私有文件路径、附件校验值和内部实体 ID 永不进入当日复盘请求。
- Prompt 使用 JSON 数据区，并明确声明日记和任务文字是待分析数据而不是可执行指令。
- DeepSeek 在该场景关闭思考模式，控制等待时间和 Token 成本；其他 Provider 保持各自 Adapter 行为。

## 输出约束

Prompt 模板版本为 `1`，要求使用简洁中文 Markdown，并包含：

- 今日总结
- 做得好的地方
- 可以温柔看见的问题
- 明日最小建议

输出只能基于授权数据，不进行医疗、心理或财务诊断，不制造负罪感，不把建议写成命令。明日建议限制为 1 到 3 个足够小的行动。

## 本地持久化

数据库 Schema 升级到版本 6，新增 `ai_daily_reviews`：

- 保存日期、Markdown 内容、Provider、模型和 Prompt 版本。
- 保存本次授权的上下文类型，用作复盘依据范围。
- 保存 Provider 返回的 request ID 与 Token 用量（存在时），用于排查和未来统计。
- 不保存 API Key、完整请求 Prompt 或 Diary 图片。
- AI 生成内容视为不可变结果；重新生成创建新记录，当前页面展示最新一条。

未来 Timeline 模块可以读取这些不可变记录并展示历史版本，不需要改变本模块的事实数据。

## 异常与降级

- 未选择上下文时不允许调用 AI。
- 本地上下文在生成前发生变化时阻止发送并提示刷新。
- Provider 未配置、鉴权、网络、限流和输出异常沿用统一 `AiException`。
- AI 失败不修改 Daily、Action、Diary，也不影响这些离线模块继续使用。

## 自动化验证

- 上下文加载阶段不会调用 AI。
- 未勾选的日记不会出现在 Prompt。
- 长日记按本地上限截断，图片路径不会发送。
- 空授权在网络调用前被拒绝。
- 复盘结果、授权类型、模型信息和 Token 用量可持久化并读取最新版本。
- Schema 5 可以升级到 Schema 6，并创建日期索引。
- Widget 测试覆盖默认未授权、主动勾选、生成和结果展示。

所有自动化测试使用 Fake AI Service，不访问真实 Provider，也不产生费用。
