# Stage 3：AI Friend 单轮陪伴

## 模块目标

AI Friend 的首个版本提供“聊聊此刻”的单轮倾听场景。它接住用户主动表达的感受，但不伪装成人类、不鼓励依赖、不替代现实关系或专业服务。

本批次不实现多轮对话、长期记忆、主动读取历史或人格养成。每次输入都是独立请求，避免在安全策略和记忆治理尚未成熟时形成不可控上下文。

## 用户流程

1. 用户从“今天”页点击“聊聊此刻”。
2. 页面明确说明只发送当前输入框中的文字，不读取日记、状态、任务、历史复盘或过去对话。
3. 用户可以选择是否把这次交流保存到本机，默认保存。
4. 普通或敏感主题通过当前配置的 AI Provider 获得单轮回应。
5. 明确危机表达由本地固定安全回应处理，原文不会发送给 AI Provider。
6. 已保存交流可以从本机物理删除；未保存交流离开页面后不可恢复。

## 安全分层

### 日常陪伴

- 先承接感受，再进行简短、不评判的回应。
- 最多提出一个温和、容易回答的问题。
- 不声称拥有未提供的记忆，不承诺“永远陪伴”，不引导用户排斥现实关系。

### 敏感主题

本地规则识别医疗、心理、法律、财务等关键词，在通用陪伴 Prompt 上增加专业边界：只提供情绪支持和一般信息，不给诊断、处方、投资、法律结论或重大决定建议，并在需要时建议联系合格专业人士。

### 危机表达

本地规则优先识别明确的自伤、自杀或伤害自身表达：

- 不调用外部 AI，避免模型延迟、拒答或不稳定输出。
- 固定回应优先确认立即危险、建议不要独处、移开可能造成伤害的物品、联系可信任的人和当地紧急服务。
- 中国大陆用户可看到 110/120 提示，同时保留“当地紧急服务”的通用表达。
- 明确说明 AI 不能替代现实中的紧急支持。

关键词分类只是第一层防护，不是心理状态诊断，也不能保证识别所有表达。后续多轮场景必须引入更完整的安全评估、区域化援助资源和红队测试。

## Prompt 与隐私

- Prompt 模板版本为 `1`。
- 用户文字放入 JSON 数据区，并声明它是待回应内容而不是系统指令。
- 不附带任何 LifeOS 业务实体、内部 ID、日记、图片、统计或历史消息。
- Provider 回应限制为 100 到 300 个汉字，DeepSeek 关闭思考模式以控制等待时间和费用。
- 日志不记录用户输入、AI 回应或完整 Prompt。

## 本地持久化与删除

数据库 Schema 升级到版本 7，新增 `ai_friend_exchanges`：

- 保存用户文字、AI 回应、安全级别、Prompt 版本和创建时间。
- Provider 实际参与时保存 Provider、模型、request ID 和 Token 用量。
- 本地危机回应不保存 Provider 或模型信息，便于审计是否发生外部调用。
- 用户关闭“保存这次交流到本机”时不写入 SQLite。
- 用户执行删除时物理删除该次交流正文；未来同步需要的删除 tombstone 必须与敏感正文分离设计。
- API Key、历史上下文和完整请求 Prompt 不进入该表。

## 自动化验证

- 日常内容只发送本次输入文字并可保存。
- 用户关闭保存后，Provider 回应不会写入 SQLite。
- 危机表达不调用 AI，并展示本地安全回应。
- 危机优先级高于普通敏感主题。
- 敏感主题 Prompt 包含专业边界。
- 空文本和超长文本在网络调用前被拒绝。
- Provider 交流和本地安全回应均可正确持久化。
- 删除会从 SQLite 物理移除敏感正文。
- Schema 6 可以升级到 Schema 7，并创建最新交流索引。
- Widget 测试覆盖普通单轮交流、删除和危机本地降级。

所有测试使用 Fake AI Service，不调用真实 Provider，也不产生费用。
