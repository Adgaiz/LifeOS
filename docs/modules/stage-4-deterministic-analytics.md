# Stage 4：确定性统计与趋势

## 模块目标

首版 Analytics 帮助用户看见一段时间内的状态与行动变化。统计不是评分，也不用于证明用户“足够自律”；它只把已经记录的事实转换成可理解的趋势。

所有计算均在本机完成，不调用 AI、不上传原始记录、不修改 Daily、Action 或 Goal。未来 AI Analyst 只能在用户明确授权后读取这些聚合结果。

## 用户流程

1. 用户从“今天”页点击“成长趋势”。
2. 页面默认展示近 7 天，可以切换近 30 天。
3. 页面展示记录覆盖、行动、运动和目标摘要。
4. 用户查看睡眠、情绪与精力、体重趋势。
5. 下拉刷新后从 SQLite 重新读取并计算。

## 首批指标

### 状态与健康

- 记录天数及周期覆盖率。
- 平均睡眠时间与每日趋势。
- 平均情绪、平均精力及每日趋势，量表保持 Daily 的 1–5 级定义。
- 最新体重、周期内首末两次体重变化与每日趋势。
- 运动天数与运动总分钟数。

### 行动与目标

- 行动完成率 = 状态为“已完成”的行动数 ÷ 周期内全部行动数。
- “部分完成”单独计数，但不计入已完成分子。
- 进行中目标平均进度 = 先计算每个目标关键结果的平均进度，再计算所有进行中目标的平均值。

## 日期与缺失值规则

- 近 7 天和近 30 天都包含用户本地今天。
- SQLite 使用 `YYYY-MM-DD` 的本地日历日期进行闭区间查询。
- 没有记录的日期不补 0，平均值只使用实际存在的字段。
- 同一本地日期因时区变化出现多条 Daily 时，采用 `updated_at` 最新的一条，防止重复计数。
- 体重变化至少需要两次有效记录；只有一次时仅展示最新值。
- 没有行动时完成率显示“暂无”，不显示误导性的 0%。

## 架构设计

- `AnalyticsRepository` 只读查询 Daily、Action 和当前进行中 Goal。
- `AnalyticsService` 负责日期范围、去重、聚合和公式，不依赖 Flutter 或 Drift。
- `AnalyticsReport` 保存本次即时计算结果，不新增统计快照表，避免缓存与事实数据不一致。
- 趋势图使用 Flutter `CustomPainter`，不新增图表依赖。
- 页面入口放在“今天”，不增加第六个底部导航项。

## 自动化验证

- 7/30 天周期边界正确且包含今天。
- 缺失值不按 0 参与平均。
- 同日多时区记录取最后更新值。
- 睡眠、情绪、精力、体重、运动、行动和目标公式正确。
- SQLite 只返回日期范围内且未删除的数据，并只统计进行中目标。
- Widget 测试覆盖本地指标展示和周期切换。
- Today Widget 测试覆盖“成长趋势”入口。
