# Stage 4：Timeline 人生时间线

## 模块目标

Timeline 的首个版本帮助用户主动保存值得记住的人生节点。它不是日记的重复列表，也不会把所有行为都包装成“成就”，而是让用户自己决定哪些时刻对人生有意义。

本批次实现手动事件的创建、按日期回顾、编辑和删除。Vision、Goal、Daily、Diary 与 AI 结果的自动聚合暂不启用，避免系统未经确认替用户定义重要事件。

## 用户流程

1. 用户从底部“足迹”入口进入人生时间线。
2. 空状态引导用户记录第一个重要节点。
3. 用户选择发生日期和节点类型，填写标题与可选说明。
4. 节点按发生日期倒序排列，并按年月分组。
5. 用户可以编辑或删除自己手动创建的节点。

## 节点类型

- 新的开始
- 里程碑
- 重要转折
- 珍贵记忆

类型只帮助回顾和识别，不用于评分、排行或制造成长压力。

## 数据设计

数据库 Schema 升级到版本 8，新增 `timeline_events`：

- `occurred_on` 使用本地日历日期，避免跨时区改变事件日期。
- `event_type` 保存节点类型。
- `title` 和 `description` 保存用户主动输入的事实内容。
- `source_type`、`source_id` 为未来系统事件保留可追溯来源。
- `created_at`、`updated_at`、`version` 和 `deleted_at` 延续离线优先与未来同步基线。

系统事件预先建立 `source_type + source_id + event_type` 条件唯一索引，保证未来从业务实体聚合时幂等；当前手动事件的 `source_id` 为空，不受该唯一索引限制。

## 业务边界

- 事件标题为 1–80 个字符，说明最多 2000 个字符。
- 发生日期不能晚于用户本地今天。
- 手动事件可以编辑和软删除。
- 未来系统事件默认不可由手动编辑器改写或删除，应回到来源实体处理。
- Timeline 不调用 AI，也不上传任何数据。

## 自动化验证

- 手动节点创建时会规范化文本并记录版本。
- 编辑会保留 ID、创建时间和来源，同时递增版本。
- 未来日期、空标题和过长内容会被拒绝。
- SQLite 按发生日期倒序读取，并过滤已删除事件。
- Schema 1–7 可以升级到 Schema 8，并创建两个 Timeline 索引。
- Widget 测试覆盖空状态和首个节点创建流程。
