# ADR-0001：采用离线优先的模块化架构

- 状态：Accepted
- 日期：2026-07-29
- 决策者：LifeOS 项目

## 背景

LifeOS 的核心价值是帮助用户每天记录并长期回顾。网络、后端或 AI Provider 暂时不可用时，Daily、Action 和 Diary 等核心记录仍必须工作。项目早期由个人使用和维护，暂不需要微服务带来的部署复杂度。

## 决策

1. Flutter 客户端采用 Offline-first，以 SQLite 作为 UI 的即时数据源。
2. 移动端按 Feature-first 组织，并在功能内部保持 presentation、application、domain、data 分层。
3. Spring Boot 后端采用模块化单体，模块之间通过公开应用服务或领域事件协作。
4. 业务层依赖 Repository 和 AI 端口，不直接依赖数据库、HTTP Client 或模型厂商 SDK。
5. Phase 1 免登录；账户、云同步和服务端统一 AI 在后续阶段引入。

## 结果

- 核心记录可以在断网时立即保存。
- 本地实体从首期开始使用全局 ID、版本、软删除和明确的时间语义，为同步演进预留空间。
- AI 和同步属于可降级能力，失败不能导致核心记录入口不可用。
- 在当前规模下不引入微服务、消息中间件或分布式事务。

## 验证方式

- 自动化测试覆盖断网保存和本地读取。
- 架构评审检查 UI 不直接访问 DAO、HTTP 或 AI SDK。
- 后续同步模块验证幂等、重试与长文本冲突保留。
