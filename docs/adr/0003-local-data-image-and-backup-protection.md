# ADR-0003：MVP 本地数据、图片与备份保护

- 状态：Accepted
- 日期：2026-07-29
- 决策者：LifeOS 项目
- 部分被替代：[ADR-0004：采用加密 Drift 数据库与用户控制的加密备份](0004-encrypted-database-and-user-controlled-backup.md)
- 复审触发：公开发布、引入云备份/账户同步、设备威胁模型变化

## 背景

Phase 1 是 Android 单用户、免登录的个人版本。SQLite 将保存日记、情绪、健康和行动等敏感信息，Diary 还需要保存图片。API Key 属于高敏感凭据。

应用层数据库加密能够降低设备文件被直接复制后的泄露风险，但会增加原生依赖、迁移、备份、性能和故障恢复复杂度。Android 应用沙箱和设备锁可以提供基础保护，但不能防御已 root、已解锁设备或调试备份等全部场景。

## 决策

1. MVP 使用标准 SQLite/Drift，不在首个工程基线中引入 SQLCipher。
2. 数据库和图片只保存在 Android 应用私有目录，不使用公共相册或公共文件目录作为事实源。
3. API Key 必须保存在 Android Keystore 封装的安全存储中，禁止进入 SQLite、配置文件、日志、崩溃报告或 Git。
4. Diary 图片以文件保存；SQLite 仅保存相对路径、类型、尺寸、大小、校验值和生命周期状态，不保存图片 BLOB。
5. 在实现经过验证的加密备份/导出前，数据库和 Diary 图片不自动加入云备份；应用卸载可能导致本地数据丢失，产品内必须明确提示。
6. 日志和监控不得包含日记正文、健康明细、图片内容、完整 AI Prompt 或凭据。
7. 在写入真实长期数据前，必须完成数据导出与恢复方案的设计；导出内容应支持加密并包含附件校验清单。

## 理由

- 当前是个人单设备 MVP，先降低原生加密插件与数据库迁移的失败面。
- API Key 与业务数据使用不同的风险控制，数据库暂不加密不代表凭据可以降级保护。
- 明确禁用未验证的自动备份，避免敏感内容无提示进入厂商云端。
- Repository 边界保持不变，后续可通过替换数据库实现引入 SQLCipher。

## 已知风险

- 已 root、已解锁或被调试控制的设备可能读取标准 SQLite 和图片文件。
- 应用卸载或设备损坏时，如果用户没有主动导出，Phase 1 数据可能无法恢复。
- 禁用自动备份提高隐私确定性，也提高了数据丢失风险。

## 后续措施

- Diary 模块实现前完成图片导入、EXIF 隐私、孤儿文件清理和删除恢复测试。
- 首个真实数据版本前设计加密导出与恢复流程。
- 账户/同步阶段重新评估 SQLCipher、服务端加密、密钥恢复和多设备威胁模型。
- 在 vivo X100s 上测量数据库迁移与图片读写性能，保留基准数据。

## 验证方式

- 自动化扫描确保仓库不包含密钥。
- Android 配置测试确认敏感数据未被无提示自动备份。
- 集成测试验证数据库与图片只写入应用私有路径。
- 恢复演练验证导出包中的 Markdown、结构化数据和附件校验值一致。
